- Language Courses and Packages: one shared searchable price editor/currency selector, clear errors instead of false empty lists, explicit currency-change confirmation, private Save Draft, comparison, review, publication, revision restoration and non-destructive archive. - Academic programme tuition: uses the same currency registry, preserves unchanged legacy denominations, requires confirmation before changing a priced record’s currency, and revalidates precision through review/publication. Programme parent links and existing free-text fee guidance remain intact.
- Settings → Currencies: Superadmin-only registry management for name, code, symbol, decimal precision and active status. Codes cannot be renamed or deleted. Referenced precision is protected, including programme tuition and drafts/revisions; the seven Agreement currency precisions are fixed. New currencies are available to supported catalogue forms only, never automatically to Agreement calculations. Inactive currencies can be retained on existing records.
- Settings: self-service display name and existing secure password change. Display name is used by the dashboard and account menu. It is separate from server-assigned identity/designation and is never trusted for authorization or legal representative identity. No email, role or permission fields are writable in the profile form.
- Team & Permissions: dedicated `/admin/team`, retaining the existing staff creation/matrix and Superadmin checks. `/admin/users` redirects there. Settings contains a navigation link, not staff provisioning controls.

## Read-only production findings and legacy ambiguity

The targeted read-only query found **0 `language_courses` rows**, **15 countries**, **6 universities**, and **10 programmes**. The three existing public course cards are defined in `coursesPageCopy`; they were not database records and therefore could not appear in the old database-only CMS. No real course rows were missing from that query, and none were fabricated or inserted.

The new course list labels those actual source cards as **Website default — not a database record**. Opening one loads its effective text. An explicit Save Draft creates a private managed override linked by a stable `source_key`; publication updates the corresponding card, without duplicating it. Initial effective source wording is captured in revision history. A unique source index prevents duplicate published overrides. Ordinary database courses and their IDs are retained separately.

Legacy course numbers were shown with a fixed £ label, but that does not prove their denomination. Nullable currency fields stay null; the CMS flags unconfirmed legacy amounts and requires explicit confirmation when assigning a currency. Unconfirmed course prices are not publicly labelled as a guessed denomination. GBP is retained as an **inactive legacy registry entry**, in addition to the seven requested defaults. Legacy package displays were explicitly USD and remain USD unless deliberately changed and confirmed. No exchange-rate conversion is implemented or implied.

The language application workflow retains its existing taxonomy and routes. New catalogue courses use the existing general/Other enquiry flow; no new application schema or student records were introduced. Existing course links and source-card highlights remain intact.
